# CLI Web 元素入库截图：被遮挡、未滚动可见、未恢复窗口层级

已提交产品仓库 Issue：[uiautoma/desktop #75](https://github.com/uiautoma/desktop/issues/75)，标签 `bug`，关联验收跟踪 #50。

结论：相对本次用户明确要求，这是产品缺陷和行为缺口，不能仅通过更换 `capture web` 参数完整解决。上次使用 `--no-highlight` 是遮挡截图的直接触发条件；该参数是合法选项，帮助描述为关闭红框预览。当前实现将原生窗口激活绑定在可选预览中，实际截图路径没有独立保证浏览器不被遮挡。

用户期望：记录原窗口状态 → 临时将正确浏览器窗口置于前台 → 将目标元素及 iframe 置于可见位置 → 等待布局稳定并截图 → 成功或失败后恢复浏览器原来的层级。恢复不应只等同于重新激活某个窗口。

## 两轮受控结果

同一浏览器、同一输入框、同一遮挡窗口。每次捕获前用 CLI 激活 UIAutoma 作为遮挡窗口，确认它处于前台且位于浏览器上方。以约 10 ms 间隔读取原生前台 HWND 和两个窗口的相对层级；窗口控制和捕获均使用 `uia.exe`。

| 场景 | 两轮结果 | 与期望的差异 |
| --- | --- | --- |
| 元素在视口内，`--no-highlight` | 2/2 未观察到浏览器进入前台，PNG 拍到 UIAutoma 内容 | 截图被遮挡；前台未改变是因为没有执行必要激活，并非完成了临时置顶后的恢复 |

## 实现链路与定位

1. [CLI 参数](D:/code/desktop/cli/command/src/main.rs:188)将 `--no-highlight` 描述为不显示红框；[参数映射](D:/code/desktop/cli/command/src/main.rs:777)只传递 `highlight=false`。
2. [Runtime 入库](D:/code/desktop/runtime/services/pipe_server.py:649)仅在 `highlight=true` 时先执行观察高亮。[实际捕获](D:/code/desktop/runtime/services/pipe_server.py:661)和保存不具备独立的前台保证，也没有包裹整个流程的窗口状态恢复。
3. [Provider 高亮路径](D:/code/rust_uia/src/main.rs:6050)调用原生 `activate_window`；[普通引用捕获](D:/code/rust_uia/src/main.rs:5897)主要取得 DOM 几何与浏览器截图上下文，没有对应的原生激活/恢复步骤。
4. [浏览器捕获](D:/code/desktop/chrome/engine/playwright/observation_sessions.mjs:272)仍会 `page.bringToFront()`。本次实测它选择了目标页面，但没有消除原生窗口遮挡。不能将其当成 Windows HWND 激活的保证。
5. [DOM 捕获](D:/code/desktop/chrome/engine/playwright/capture_observation.mjs:78)读取 `boundingBox()`，没有先把目标滚动到视口内。高亮几何路径也只读取边框。
6. [PNG 实现](D:/code/rust_uia/src/element_library_store.rs:3290)从桌面 `GetDC(NULL)` 取屏幕像素并 [BitBlt](D:/code/rust_uia/src/element_library_store.rs:3322)，因此会保存其它窗口的遮挡内容；蓝框是之后绘制的，不能证明底下的像素来自浏览器。
7. [截图不可用分支](D:/code/rust_uia/src/element_library_store.rs:1128)仍保存定位快照和目录记录；CLI 的成功响应没有单独暴露本次截图缺失。

[README](D:/code/desktop/cli/README.md:1252)明确写明原生激活属于预览，`--no-highlight` 关闭这层预览。因此当前行为符合这段现有说明；但不满足用户要求的截图合同。不能把“去掉该参数后截图正常”作为全部问题已解决的结论。

## 产品侧建议与验收

- 将截图准备与红框预览分开。无论是否 `--no-highlight`，在开始任何激活之前记录原状态，准确识别页面对应的原生窗口，保证拍摄时无遮挡。`--no-highlight` 只控制预览红框。
- 将目标及必要的 iframe 祖先滚入可见位置，再等待布局稳定并重新取得几何，避免使用滚动前的屏幕坐标。
- 用覆盖预览、捕获和提交的 `try/finally` 或状态守卫恢复原前台、浏览器层级及原 topmost/最小化状态。仅再次激活原前台窗口，不能保证完整恢复原层级。
- 明确表达截图是否生成；不要让缺失 PNG 的成功响应看起来与完整资产相同。若资产已经提交，不自动重放保存请求。
- 回归覆盖默认参数、`--no-highlight`、被普通窗口遮挡、离屏、最小化、iframe/Shadow DOM，以及截图失败、提交失败、超时后的恢复。还应验证已有置顶窗口状态和浏览器各窗口身份。

本测试 Agent 只提供复现和建议，产品修复由上述源码项目处理。
