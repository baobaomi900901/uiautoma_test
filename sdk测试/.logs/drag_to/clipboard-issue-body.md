## 问题归属

本 issue 跟踪本地 Win32 SDK 测试脚本的剪贴板稳定性缺口，不认定为 Win32Element.drag_to 产品实现缺陷。
脚本位于测试者本地 `win32/test_win32_drag_to.py`，测试根目录独立于 desktop 仓库；关联辅助函数在 `win32/test_win32_clipboard_input.py`。仓库中未必存在这些本地测试文件。

## 代码中确认的缺口

`read_state()` 写入唯一标记、点击复制按钮一次，此后两秒内只重读剪贴板。如果复制端那一次写入失败，后续重读不能重新产生 JSON。唯一标记防止误读旧数据的行为应保留。

`restore_text()` 调用写入和读回校验各一次；辅助函数 OpenClipboard 失败立即抛出 OSError，没有针对短暂不可用的限时重试。因此辅助流程可造成整轮验收失败，且剪贴板文本无法恢复。

## 建议修复与验收

- 对可恢复的剪贴板打开失败加入有截止时间的重试，保持其他错误的明确报告。
- 未得到本轮新 JSON 时，有限次数重新点击复制按钮；记录重试次数及最终错误。
- 不自动重做 drag_to，避免改变待校验状态。
- 恢复原文本同样限时重试，最终失败仍必须报告清理失败，不能伪装 PASS。
- 覆盖短暂失败后成功、持续失败超时、旧标记未被替换及清理失败不影响其他资源释放的检查。
