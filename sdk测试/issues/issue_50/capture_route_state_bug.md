## 来源

关联 #50，D4 验收中发现的跨页面导航变体。测试者于 2026-09-10 提供真实界面复现。
这不是仅在元素/图像列表之间切换，而是通过左上角导航离开“元素与图像库”再返回。

## 复现步骤

1. 点击“捕获元素”，App 最小化并进入元素捕获模式。
2. 保持捕获模式，手动恢复 App。此时按钮置灰，显示“捕获中…”。
3. 通过左上角导航切换至其他页面，再返回“元素与图像库”。
4. 原捕获仍在进行，但按钮恢复正常可点击状态。再次点击“捕获元素”，按钮重新显示“捕获中…”。
5. 按一次 Esc，未退出捕获模式，反而使 App 最小化；再次按 Esc 才退出捕获。

## 预期

- 捕获忙碌状态与实际任务生命周期一致，不因页面卸载/重建丢失。
- 跨页面导航后返回，仍显示“捕获中…”并禁止重复启动及冲突操作。
- 一次有效 Esc 应取消当前捕获并正确收尾；取消完成后才恢复可用状态。
- 失败取消仍保留重试能力，不能通过提前清除忙碌状态掩盖任务未结束。

## 实际影响

用户可以在原捕获尚未结束时重复触发捕获入口；随后取消出现需要两次 Esc、窗口意外
最小化的表现。尚未通过运行时日志确认是否真正创建了两个 Provider 会话，不能将其
直接描述为已证实的双会话并发。

## 只读源码线索

- `app/src/App.tsx`：`mainRoute === "elementLibrary"` 时才渲染 `ElementLibraryPane`，
  导航离开该页面会卸载组件。
- `app/src/ElementLibraryPane.tsx`：`newPickBusy` 为组件内 `useState(false)`；
  重新挂载会恢复初始值。按钮文字依赖该状态，禁用条件包含 `captureOrValidationBusy`。
- `app/src/useElementLibraryCaptureEscape.ts`：本地 Esc 处理依赖各捕获 busy 状态。

这些线索与返回页面后按钮状态丢失一致；两次 Esc 的完整事件顺序、旧任务回调及
Provider 会话状态仍需开发结合日志确定，未宣称已完成根因复现或修复。
