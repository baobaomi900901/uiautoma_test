## 测试者确认的补充交互要求：捕获期间禁止切换页面

关联 #50。本条由测试者明确提出并确认，补充到 #55 的修复验收范围。

- 进入“捕获元素”或“重新捕获”模式时，禁用左上角页面切换菜单；即使手动恢复 App 窗口，也不能通过该菜单离开当前页面。
- 禁用应从进入捕获开始持续到任务成功完成或取消成功并完成收尾，不能在仅发出取消请求时提前解除。
- 取消失败时继续禁用页面切换，保留停止/取消重试能力；重试成功并完成收尾后恢复导航。
- 菜单禁用不能代替任务状态的正确管理：捕获忙碌状态仍应随实际任务保存，避免其他导航路径或页面重建导致状态丢失。

### 补充验收

1. 分别启动“捕获元素”和“重新捕获”，手动恢复 App，确认左上角页面菜单无法切换页面；鼠标及该控件支持的键盘操作均不能绕过。
2. 正常完成捕获或按 Esc 成功取消后，确认收尾完成、页面切换恢复可用。
3. 取消失败场景由开发协助注入：页面切换仍被禁用，停止/取消重试可用；重试成功后恢复导航。
4. 不应出现未完成捕获却解锁、重复启动捕获、取消后永久锁定导航的情况。

本条明确覆盖“捕获元素 / 重新捕获”。其他入口不因本条自动视为新增验收范围。
