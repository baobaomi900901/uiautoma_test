# Web 表单元素 API 复测清单

目标页面：<https://baobaomi900901.github.io/xpath/#/iframe-shadow-form>

元素库：`D:\code\元素库\260902_web元素`

页面左侧是 Ant Design 表单，右侧是原生 HTML 表单。两侧必须分别执行相同的 API
用例，不能只验证一侧后推断另一侧。

## 每次运行的公共前置

1. 打开目标 URL，等待页面加载完成、iframe 和 shadow DOM 可访问。
2. 通过元素库获取 `web靶场_表单测试_控制表单组件id是否为动态的开关`。
3. 先读取开关当前状态；只有当前为开启时才点击一次，使其变为关闭。不要无条件点击，
   否则当前已关闭时会被重新打开，导致元素库固定 ID 失效。
4. 使用 `web.wait_appear()` 或元素 `wait_appear()` 等待目标元素；元素不在视口时，
   用浏览器滚动或元素 `scroll_to()`，不修改页面数据。
5. 每个赋值/选择/勾选动作都执行对应侧的提交按钮：
   - Ant：`web靶场_表单测试_ant_按钮_提交`
   - 原生：`web靶场_表单测试_原生_按钮_提交`
6. 用 SDK 或原生剪贴板读取提交值，和预期逐字段比较；随后点击对应重置按钮：
   - Ant：`web靶场_表单测试_ant_按钮_重置`
   - 原生：`web靶场_表单测试_原生_重置`
7. 每个 API 用例结束时确认表单回到初始状态。整个脚本 finally 中关闭测试网页，
   释放 Browser/Package、恢复剪贴板和临时文件。

## 第一组：文本和赋值 API

优先覆盖 `input()`、`clipboard_input()`、`set_value()`、`get_value()`、`get_text()`、
`get_attribute()`、`get_all_attributes()`。

- 文本输入：普通 ASCII、中文、Emoji、空字符串、首尾空白、多行文本。
- 密码/邮箱/数字：分别验证输入值、类型约束、提交值和重置值；不在日志打印密码原文。
- `input()`：覆盖覆盖/追加、键盘/自动化模式、点击前聚焦、延时和非法参数。
- `clipboard_input()`：覆盖/追加、Unicode、剪贴板恢复；提交后读取并重置。
- `set_value()`：覆盖控件值并通过提交值确认；检查返回 None 和动作结果。
- 读取 API：回读实时值/文本/属性，与提交前后的原生 DOM 值独立交叉核对。

## 第二组：选择、勾选和状态 API

覆盖 `select()`、`select_by_index()`、`select_multiple()`、
`select_multiple_by_index()`、`check()`、`is_checked()`、`is_enabled()`。

- 单选：逐项选择，测试 exact/contains/regex 或当前实现支持的模式，提交后重置。
- 多选：选择一项、多个项目、追加/覆盖、索引0/中间/末项和越界；确认顺序与提交值。
- radio：Ant 与原生各选择男/女/其他，确认只有一个选中。
- checkbox：全选、单项、多个组合和取消，确认 checked 状态及提交值。
- 状态读取：重置前后分别读取 `is_checked()`、`is_enabled()`，不只依赖按钮样式。

## 第三组：结构、定位和几何 API

覆盖 `find()`、`find_all()`、`wait_appear()`、`wait_disappear()`、`parent()`、
`children()`、`child_at()`、`previous_sibling()`、`next_sibling()`、`get_bounding()`、
`get_anchor_position()`、`scroll_to()`。

- 两侧各确认元素唯一定位；相似选择器确认多项结果数量和顺序。
- 使用滚动后重新读取边界，验证视口外元素能够定位。
- 结构关系以稳定控件（表单容器、提交按钮、重置按钮）作参照，不固化易变的完整子节点数。
- `get_bounding()` 和锚点坐标在滚动前后分别记录，区分 viewport 坐标和页面坐标。
- wait API 覆盖已有元素、未命中超时和重置后的重新出现；动态 ID 开关关闭是前提。

## 第四组：动作、截图和浏览器生命周期

覆盖 `click()`、`dblclick()`、`hover()`、`focus()`、`drag_to()`、`screenshot()`、
`screenshot_to_clipboard()`、`execute_javascript()`、`get_scroll()`。

- click/dblclick 只点安全控件或提交/重置按钮；每次动作后按提交/重置规则恢复。
- hover/focus 验证焦点或悬停状态，不把颜色变化单独当作成功依据。
- screenshot 保存临时文件并验证尺寸/格式，结束删除；clipboard 截图结束恢复原剪贴板。
- `execute_javascript()` 只读取或设置测试页允许的表单值，执行后用提交值和 DOM 独立核对。
- 不在同一脚本混合关闭浏览器与元素动作；`close_all()`、下载/上传和对话框另立用例。

## 每个 API 的固定验收表

| 项目 | 必须检查 |
| --- | --- |
| 合同 | 当前源码签名、默认值、位置/关键字规则、返回类型 |
| Ant | 左侧控件正常路径和边界 |
| 原生 | 右侧对应控件正常路径和边界 |
| 独立参照 | DOM/提交剪贴板/文件或浏览器状态，避免只回读 SDK |
| 视口 | 必要时滚动，记录滚动前后状态 |
| 异常 | 空值、非法类型、越界、未找到、超时 |
| 恢复 | 对应提交后重置；剪贴板、页面、临时文件、浏览器连接恢复 |
| 结论 | PASS/FAIL/BLOCKED、完整日志、退出码、未覆盖项和 issue 链接 |

## 执行顺序

1. `input()`、`clipboard_input()`、`set_value()`、`get_value()`、`get_text()`。
2. `select()`、`select_by_index()`、`select_multiple()`、`select_multiple_by_index()`。
3. `check()`、`is_checked()`、`is_enabled()`。
4. `get_attribute()`、`get_all_attributes()`、`find()`、`find_all()`。
5. `wait_appear()`、`wait_disappear()`、结构关系和几何/滚动 API。
6. click/双击/hover/focus、截图和 JavaScript。
7. 最后处理浏览器生命周期、下载/上传和对话框 API。

每次只推进一个 API。当前 Web 旧证据中的 `READY_FOR_LIVE` 先按本计划重跑；历史
`VERIFIED` 也要在当前 Web Stack 和当前元素库上重新确认后再更新证据。
